# 基础版语音助手系统部署总结

## 一、系统简介

基础版语音助手系统整合了三个 AI 模型，实现完整的语音交互流程：

**数据流：**
```
语音输入 → Zipformer(语音识别) → InternVL3-1B(对话理解) → MeloTTS(语音合成) → 语音输出
   ↑                                                                              ↓
 麦克风                                                                        扬声器
```

**系统特点：**
- 端到端语音交互
- 支持中英文双语
- 基于 RK3588 NPU 加速
- 模块化设计，易于扩展

---

## 二、系统架构

### 2.1 核心组件

| 组件 | 模型 | 功能 | 大小 |
|------|------|------|------|
| **语音识别** | Zipformer | 语音 → 文字 | ~128 MB |
| **对话理解** | InternVL3-1B | 文字 → 回复 | ~1.4 GB |
| **语音合成** | MeloTTS | 文字 → 语音 | ~160 MB |

### 2.2 部署架构

```
┌─────────────────────────────────────────────────────────┐
│                    RK3588 开发板                         │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐  │
│  │   Zipformer │ →  │ InternVL3   │ →  │   MeloTTS   │  │
│  │   (ASR)     │    │   (LLM)     │    │   (TTS)     │  │
│  └─────────────┘    └─────────────┘    └─────────────┘  │
│         ↑                                    ↓          │
│    麦克风/音频文件                      扬声器/音频文件    │
└─────────────────────────────────────────────────────────┘
```

## 三、部署步骤

确保以下模型已部署：
- ✅ Zipformer: `/data/zipformer/`

## 六、系统优化建议

### 6.1 当前瓶颈

1. **串行执行**：三个模型依次执行，总延迟较高
2. **模型加载**：每次都要重新加载模型
3. **音频 IO**：文件读写增加延迟

### 6.2 优化方案

| 优化方向 | 方案 | 预期效果 |
|---------|------|---------|
| **模型常驻内存** | 启动时预加载所有模型 | 减少 2-3 秒加载时间 |
| **流式处理** | Zipformer 流式识别 + MeloTTS 流式合成 | 减少 50% 延迟 |
| **并行化** | 语音识别和对话理解部分并行 | 减少 20% 延迟 |
| **量化压缩** | 使用更轻量级模型 | 减少内存占用 |

### 6.3 下一步优化

**阶段 1：模型常驻（预计提升 30%）**
- 修改脚本，启动时加载所有模型
- 保持模型在内存中，避免重复加载

**阶段 2：流式识别（预计提升 50%）**
- 使用 Zipformer 流式识别功能
- 边录音边识别，减少等待时间

**阶段 3：增量合成（预计提升 40%）**
- MeloTTS 分段合成
- 先合成前半句并播放，同时合成后半句

## 八、故障排查

### 8.1 常见问题

**问题 1：模型文件找不到**
```
[ERROR] Zipformer 目录不存在
```
**解决：** 确认模型已部署到正确路径

**问题 2：语音识别失败**
```
[ERROR] 语音识别失败
```
**解决：** 检查音频格式是否为 WAV, 16kHz, 单声道

**问题 3：对话生成失败**
```
[WARN] 对话生成失败，使用默认回复
```
**解决：** 检查 InternVL3-1B 模型是否正常加载
