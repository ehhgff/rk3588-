# 语音助手流式处理版调试文档

## 一、版本概述

### 1.1 版本信息
- **版本名称**: 流式处理版 (Streaming Edition)
- **基于版本**: RAG科室优化版 v3.1
- **更新日期**: 2024-04-21
- **核心改进**: 流式语音识别 + 服务化架构 + TTS RKNN优化

### 1.2 与前一版的主要更新

| 更新项 | RAG科室优化版 | 流式处理版 | 改进效果 |
|--------|--------------|-----------|---------|
| **语音识别** | 离线文件识别 | **流式实时识别** | 边录边识别，延迟降低50% |
| **VAD检测** | 无 | **Silero VAD** | 自动检测语音起止 |
| **服务架构** | 脚本直接调用 | **Unix Socket服务化** | 服务常驻，响应更快 |
| **TTS引擎** | 原版TTS | **MeloTTS RKNN** | NPU加速，音质更好 |
| **启动方式** | 分别启动 | **一键启动脚本** | 简化部署流程 |
| **音频格式** | 16kHz | **44.1kHz Float32** | CD音质 |
| **语速控制** | 固定 | **可调 (0.5-2.0)** | 灵活适配场景 |
| **音量控制** | 固定 | **可调 (0-100%)** | 适配不同环境 |
| **LLM模型** | InternVL3-1B | **Qwen3-0.6B** | 更小更快 |

## 四、遇到的问题和解决方案

### 4.1 VAD相关问题

#### 问题1: TEN Framework VAD不支持ARM架构
**现象**: 
- TEN Framework VAD仅支持x86架构，无法在RK3588(ARM架构)上运行
- 导入时报错: `ImportError: cannot import name 'VAD'`

**原因**: 
- TEN Framework VAD底层使用x86特定的指令集
- 没有提供aarch64版本的预编译包

**解决方案**:
1. 卸载TEN VAD: `pip3 uninstall ten-vad`
2. 寻找支持ARM架构的VAD库
3. 最终采用Silero VAD (支持ARM，基于PyTorch)
4. 安装依赖:
   ```bash
   # torchaudio aarch64版本
   pip3 install torchaudio-2.1.0-cp310-cp310-linux_aarch64.whl
   
   # onnxruntime aarch64版本
   pip3 install onnxruntime-1.16.3-cp310-cp310-linux_aarch64.whl
   ```

#### 问题2: Silero VAD导入失败
**现象**: 
```
ImportError: cannot import name 'VAD' from 'silero_vad'
```

**原因**: 
- 使用了错误的API
- Silero VAD的正确API是`load_silero_vad`和`VADIterator`

**解决方案**:
```python
from silero_vad import load_silero_vad
import torch

model = load_silero_vad(torch.device('cpu'))
```

#### 问题3: 静音比例不对，很多语音未检测到
**现象**: 
- VAD检测过于灵敏，杂音也会触发录音
- 或者检测不到正常语音

**原因**: 
- 阈值设置不当
- 连续帧数设置不合理

**解决方案**:
1. 调整VAD阈值为0.7 (平衡灵敏度和准确性)
2. 设置连续5帧检测到人声才开始录音
3. 0.7秒无人声停止录音
```python
threshold = 0.7
SPEECH_FRAMES_TO_START = 5
SILENCE_FRAMES_THRESHOLD = 23  # 0.7秒
```

### 4.2 语音识别相关问题

#### 问题4: 语音识别最后一个字识别不出来
**现象**: 
- 识别结果缺少最后一个字或几个字
- 例如: "我肚子痛" 识别为 "我肚子"

**原因**: 
- 录音停止过早，尾音未被捕获
- Zipformer缓冲区数据不完整

**解决方案**:
1. 延长静音检测阈值到0.7秒
2. 增加尾部静音缓冲0.5秒
3. 录音结束后继续处理缓冲区2秒
4. 连续5帧人声触发录音，确保开头完整
```python
SILENCE_FRAMES_THRESHOLD = 23      # 0.7秒
SILENCE_FRAMES_TAIL = 17           # 0.5秒尾部缓冲
# 录音结束后继续处理2秒
end_time = time.time() + 2.0
while time.time() < end_time and len(streaming_buffer) > 0:
    # 处理剩余音频...
```

#### 问题5: VAD和Zipformer不同步
**现象**: 
- 前半秒无人声的音频没有进入Zipformer
- 流式识别结果不完整

**原因**: 
- 前半秒无人声的音频被丢弃
- Zipformer缓冲区管理不当

**解决方案**:
```python
# 前半秒无人声的音频进入 Zipformer，后半秒不进入
if silence_frame_count <= SILENCE_FRAMES_HALF:
    streaming_buffer.append(audio_data)  # 进入Zipformer
elif silence_frame_count <= SILENCE_FRAMES_THRESHOLD:
    streaming_buffer.append(audio_data)  # 继续录制但不进入Zipformer
```

### 4.3 RAG相关问题

#### 问题6: RAG检索结果显示为数字和字母代号
**现象**: 
- RAG返回结果类似: `\u4f60\u597d\u4e16\u754c`
- 不是可读的中文文本

**原因**: 
- 对Unicode转义序列进行了错误的清理
- 使用了`encode('utf-8').decode('unicode_escape')`导致双重编码

**解决方案**:
```python
# 错误做法 (导致问题)
# response_clean = response.replace('\\/', '/').encode('utf-8').decode('unicode_escape')

# 正确做法 (直接解析JSON)
data = json.loads(response)
results = data['data']['results']
```

#### 问题7: RAG参考内容不全
**现象**: 
- 参考内容被截断，只显示前100个字符
- LLM无法获取完整的医学知识

**原因**: 
- 代码中使用了`r['answer'][:100]`截断答案

**解决方案**:
```python
# 错误做法
# prompt += f"{i}. [{r['department']}] {r['answer'][:100]}\n"

# 正确做法 (使用完整答案)
prompt += f"{i}. [{r['department']}] {r['answer'][:150]}\n"
```

### 4.4 TTS相关问题

#### 问题8: TTS合成的语音只有哼哼声
**现象**: 
- TTS服务运行正常
- 但生成的音频只有"哼哼"的噪音，没有正常语音
- 其他音频播放正常

**原因**: 
1. 音频格式不匹配 (MeloTTS生成的是44.1kHz Float32)
2. TTS服务没有在工作目录运行，导致词典加载失败
3. 缺少`--disable_bert`参数

**解决方案**:
1. 修正播放格式参数:
   ```python
   # MeloTTS生成的是 44100 Hz Float 32 bit 音频
   cmd = ["aplay", "-D", PLAY_DEVICE, "-r", "44100", "-f", "FLOAT_LE", "-c", "1", output_file]
   ```

2. 确保在MELOTTS_DIR目录下运行:
   ```python
   result = subprocess.run(
       cmd,
       env=env,
       capture_output=True,
       text=True,
       timeout=60,
       cwd=MELOTTS_DIR  # 关键：在正确的工作目录下运行
   )
   ```

3. 添加`--disable_bert`参数:
   ```python
   cmd = [
       "./melotts_demo",
       "--input_text", text,
       "--encoder_model_path", ENCODER_MODEL,
       "--decoder_model_path", DECODER_MODEL,
       "--output_filename", output_file,
       "--language", "ZH",
       "--speed", str(speed),
       "--disable_bert", "true"  # 禁用BERT加速推理
   ]
   ```

#### 问题9: 音频播放阻塞VAD检测
**现象**: 
- TTS播放时，VAD无法检测新的语音输入
- 系统处于阻塞状态

**原因**: 
- 使用`subprocess.run`同步播放，阻塞主线程

**解决方案**:
```python
# 异步播放，不阻塞VAD检测
subprocess.Popen(
    cmd,
    stdout=subprocess.DEVNULL,
    stderr=subprocess.DEVNULL
)
```

#### 问题10: TTS语速和音量调整
**现象**: 
- 默认语速过快或过慢
- 默认音量过大或过小

**解决方案**:
```python
# 语速调整 (经过多次测试，最终确定为0.6)
speed = 0.6  # 范围: 0.5-2.0

# 音量调整 (设置为30%)
subprocess.run(["amixer", "-c", "1", "set", "PCM", "30%"], capture_output=True)
```

测试过程:
- 语速0.7 → 0.8 → 0.5 → 最终0.6
- 音量50% → 30%

```python
def process_audio_stream():
    """实时处理音频流，同步进行VAD和Zipformer"""
    while recording:
        if is_streaming and len(streaming_buffer) > 0:
            # 积累音频数据
            while len(streaming_buffer) > 0 and len(streaming_chunk) < STREAMING_CHUNK_SIZE:
                audio_data = streaming_buffer.pop(0)
                streaming_chunk.extend(audio_data.tolist())
            
            # 当积累了足够的音频数据时，进行流式识别
            if len(streaming_chunk) >= STREAMING_CHUNK_SIZE:
                chunk_data = np.array(streaming_chunk[:STREAMING_CHUNK_SIZE], dtype=np.int16)
                streaming_chunk = streaming_chunk[STREAMING_CHUNK_SIZE:]
                recording_frames.append(chunk_data.tobytes())
                zipformer_buffer += chunk_data.tobytes()
                
                # 调用Zipformer流式识别
                if len(zipformer_buffer) >= ZIPFORMER_CHUNK_SIZE:
                    partial_text = zipformer_streaming_recognize(zipformer_buffer)
```

```python
def tts_synthesize(text, output, speed=0.6):
    """TTS语音合成"""
    sock = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
    sock.settimeout(30)
    sock.connect(TTS_SERVICE_SOCK)
    
    request = {
        'command': 'synthesize',
        'text': text,
        'output': output,
        'speed': speed
    }
    sock.send(json.dumps(request).encode())
    response = sock.recv(4096).decode()
    data = json.loads(response)
    sock.close()
    
    if data.get('status') == 'ok':
        return True
    return False
```

### 9.1 RAG科室优化版 vs 流式处理版

| **服务架构** | 直接调用 | Unix Socket服务化 | 响应更快 |
| **LLM模型** | InternVL3-1B | Qwen3-0.6B | 更小更快 |
| **TTS引擎** | 原版TTS | MeloTTS RKNN | NPU加速 |

1. **流式语音识别**: 边录边识别，无需等待录音结束

4. **MeloTTS RKNN**: NPU加速，音质更好，速度更快
