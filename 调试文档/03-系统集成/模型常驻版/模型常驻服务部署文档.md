## 🚀 部署步骤

### 步骤 1：编译服务程序

在虚拟机上执行：

```bash
cd ~/桌面/ai/voice_assistant

# 编译服务守护进程
aarch64-linux-gnu-g++-10 -o build/model_service_daemon \
    model_service_daemon.cpp \
    -I/home/ubuntu/桌面/ai/deepseek/rknn-llm/rkllm-runtime/Linux/librkllm_api/include \
    /home/ubuntu/桌面/ai/deepseek/rknn-llm/rkllm-runtime/Linux/librkllm_api/aarch64/librkllmrt.so \
    -lpthread -std=c++11 -O2

# 编译客户端
aarch64-linux-gnu-g++-10 -o build/llm_client \
    llm_client.cpp \
    -std=c++11 -O2
```

### 步骤 2：上传到开发板

```bash
adb push build/model_service_daemon /data/voice_assistant/
adb push build/llm_client /data/voice_assistant/
adb push voice_assistant_daemon.sh /data/voice_assistant/
adb shell "chmod +x /data/voice_assistant/*"
```

### 步骤 3：启动服务

**重要**：必须在 adb shell 交互模式中启动，否则服务会被终止

```bash
# 进入 adb shell
adb shell

# 切换到服务目录
cd /data/voice_assistant

# 启动模型常驻服务（后台运行）
LD_LIBRARY_PATH=/data/internvl3 nohup ./model_service_daemon > /tmp/llm_service.log 2>&1 &

# 等待 30 秒让模型加载完成
sleep 30

# 检查服务日志
cat /tmp/llm_service.log
```

**预期输出**：
```
========================================
    模型常驻内存服务 v1.0
========================================
[Service] 正在加载 LLM 模型: /data/internvl3/internvl3-1b_w8a8_rk3588.rkllm
...
[Service] LLM 模型加载完成
[Service] 模型已常驻内存，准备提供服务
[Service] 服务已启动，socket: /tmp/voice_assistant.sock
```

### 步骤 4：测试服务

```bash
# 测试连接
./llm_client ping
# 输出：服务运行正常

# 查看模型状态
./llm_client status
# 输出：模型状态: READY

# 测试生成
./llm_client generate '你好'
# 输出：回复: Hello! How can I assist you today?
```

### 步骤 5：运行语音助手

在**另一个终端**执行：

```bash
adb shell "/data/voice_assistant/voice_assistant_daemon.sh"
```

## 🐛 故障排除

### 问题 1：服务启动后立即退出

**现象**：日志显示 "收到信号 15，正在关闭..."

**原因**：adb shell 会话结束时发送了 SIGTERM

**解决**：使用交互式 adb shell 启动服务，不要直接执行命令

### 问题 2：日志停留在 "Enabled cpus num: 4"

**现象**：日志显示 "Enabled cpus num: 4" 后没有新输出

**原因**：这不是错误！模型已经加载完成，服务正在等待客户端连接（阻塞在 accept()）

**解决**：
```bash
# 1. 检查服务进程是否存在
ps | grep model_service

# 2. 检查 socket 文件是否创建
ls -la /tmp/voice_assistant.sock

# 3. 如果以上都正常，直接测试客户端
./llm_client ping
```

**注意**：模型加载实际已完成，日志没有继续输出是因为服务进入了等待连接的状态。

### 问题 3：客户端连接失败

**现象**："错误: 无法获取响应"

**原因**：服务未启动或 socket 文件不存在

**解决**：
```bash
# 检查 socket 文件
ls -la /tmp/voice_assistant.sock

# 检查服务进程
ps | grep model_service
```

### 问题 4：生成回复为空

**现象**：客户端返回空字符串

**原因**：模型推理超时或参数错误

**解决**：检查服务日志，确认模型状态为 READY
