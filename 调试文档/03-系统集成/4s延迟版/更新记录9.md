## 1. 模型替换背景

### 替换原因

| 项目 | DeepSeek-R1-CMtMedQA (旧) | Qwen2-0.5B-Medical (新) |
|------|--------------------------|------------------------|
| 模型大小 | 2.1 GB | **762 MB** |
| 推理速度 | ~12-15 t/s | **~40+ t/s** |
| 思考链 | 有（需 enable_thinking=False 过滤） | **无**（直接输出） |
| 医疗知识 | CMeKG 蒸馏 | **CMeKG DRAG 蒸馏** |
| 部署难度 | 需专用 runtime 1.2.3 | 兼容 RKLLM 1.2.3 |
| 首 token 延迟 | ~800ms | **<200ms** |

### 核心优势

1. **模型体积缩小 64%**：2.1GB → 762MB，NPU 内存占用更低
2. **推理速度提升 3x+**：从 12-15 t/s 到 40+ t/s
3. **无思考链**：Qwen2 架构天然无思考链输出，无需过滤逻辑
4. **更小的 KV cache**：24 层 × 896 hidden_size，推理延迟更低

## 5. TTS 语音合成替换：Paroli → Matcha TTS

### 替换原因

| 项目 | Paroli TTS (旧) | Matcha TTS (新) |
|------|----------------|----------------|
| 模型类型 | VITS (RKNN) | Matcha + Vocos (ONNX) |
| 运行位置 | NPU_CORE_0 | **CPU**（`provider=cpu`）|
| 常驻方式 | C++ socket daemon | **C daemon + FIFO pipe** |
| RTF (CPU 单线程) | ~1.01（比实时慢） | **0.261**（快 3.8x） |
| RTF (CPU 4线程) | - | **0.087**（快 11.5x） |
| 模型体积 | ~50MB (RKNN) | ~60MB (ONNX) |

### 核心优势

1. **CPU 推理**：不占用 NPU，释放全部 3 个 NPU 核心给 LLM
2. **RTF 极低**：`num_threads=4` 时 RTF=0.087，6 秒音频只需 0.58 秒生成
3. **常驻 daemon**：C 程序通过 FIFO pipe 接收文本，模型只加载一次
4. **集成 sherpa-onnx**：与 ASR 共用相同推理框架

### 架构

```
streaming_vad.py (主控)
  │  tts_synthesize(text, output)
  │    → 写文本到 /tmp/tts_pipe (FIFO)
  ▼
sherpa_tts_daemon (C, 常驻)
  │  主循环: open pipe → read text → generate audio → write .wav
  │  Matcha acoustic model + Vocos vocoder
  │  num_threads=4, provider=cpu
  ▼
/tmp/tts_out_N.wav → aplay 播放
```

### 模型文件

| 文件 | 大小 | 说明 |
|------|------|------|
| `model-steps-3.onnx` | ~30MB | Matcha acoustic model |
| `vocos-22khz-univ.onnx` | ~28MB | Vocos vocoder |
| `lexicon.txt` | 2.9MB | 发音词典 |
| `tokens.txt` | 5KB | token 映射 |

### RTF 测试结果

| 配置 | 推理耗时 | 音频时长 | RTF | 加速比 |
|------|---------|---------|-----|--------|
| threads=1 | 1.73s | 6.63s | 0.261 | 1x |
| threads=2 | 0.97s | 6.47s | 0.150 | 1.8x |
| threads=3 | 0.69s | 6.60s | 0.105 | 2.5x |
| **threads=4** | **0.58s** | 6.64s | **0.087** | **3.0x** |

### C daemon 核心逻辑

```c
// 伪代码
tts = SherpaOnnxCreateOfflineTts(&config);  // 加载一次
mkfifo(pipe_path, 0666);

while (keep_running) {
    fd = open(pipe_path, O_RDONLY);     // 阻塞等待文本
    text = read(fd);
    audio = SherpaOnnxOfflineTtsGenerate(tts, text);
    SherpaOnnxWriteWave(audio.samples, ...);  // 写入 /tmp/tts_out_N.wav
    close(fd);
}
```

## 7. 当前系统架构（更新）

### 完整流水线

```
用户说话 (USB 麦克风)
  │
  ▼
Silero VAD (连续5帧检测 → 开始录音)
  │
  ├→ SenseVoice SER (NPU CORE 0, 300ms 静音触发)
  │     └→ 情感标签 → 注入 prompt
  │
  ▼
Zipformer ASR (sherpa-onnx-alsa, RKNN NPU)
  │  rule2-min-trailing-silence=0.6
  │  greedy_search 解码
  │
  ▼
streaming_vad.py (主控)
  │
  ├─ SER 情感分析
  ├─ Patient RAG (patient_data.json, Bigram Jaccard)
  │    ├→ 命中 (conf≥0.30) → 直通 TTS，跳过 LLM
  │    ├→ 离题 → 注入矫正指令 → LLM
  │    └→ 未命中 → LLM
  │
  ├─ LLM: Qwen2-0.5B-Medical (RKLLM w8a8, NPU CORE 0+1+2)
  │    └→ keep_history=1, enable_thinking=False
  │
  └─ TTS: Paroli (Piper TTS C++ daemon, CPU)
       └→ USB 音箱播放
```

### 进程架构

```
┌─────────────────────────────────────────────────────┐
│                  fast-boot-service.sh                │
│                        │                            │
│                   run.sh (启动所有服务)               │
│                        │                            │
│    ┌───────────────────┼───────────────────────┐    │
│    ▼                   ▼                       ▼     │
│ qwen3_llm_streaming patient_rag_server  sensevoice   │
│  _service.py            .py            _server.py    │
│  (Qwen2-0.5B)        (RAG 检索)       (SER)        │
│    │                                                 │
│    ▼                                                 │
│ sherpa_tts_service.py ─→ sherpa_tts_daemon (C)      │
│  (Python 管理)          (Matcha TTS, CPU, 常驻)     │
│    │                      │                          │
│    │  FIFO Pipe (/tmp/tts_pipe)                      │
│    ▼                      ▼                          │
```

## 8. NPU 核心分配

### RK3588 NPU 核心

| 核心 | 掩码 |
|------|------|
| NPU_CORE_0 | 1 |
| NPU_CORE_1 | 2 |
| NPU_CORE_2 | 4 |

### 当前分配

| 服务 | 核心 | 掩码 | 备注 |
|------|------|------|------|
| Paroli TTS | CPU | - | 纯 CPU 推理，不占用 NPU |
| SenseVoice SER | NPU_CORE_0 | 1 | `core_mask=RKNNLite.NPU_CORE_0` |
| Qwen2 LLM | NPU_CORE_0+1+2 | 7 | 三核心全开 |
| Zipformer ASR | Auto | - | `--provider=rknn` |

### 冲突分析

| 可能冲突的组合 | 是否同时运行 | 结论 |
|---------------|-------------|------|
| TTS ↔ SER | ❌ 不会（TTS 在 LLM 之后） | 无冲突 |
| TTS ↔ LLM | ❌ 不会（TTS 纯 CPU） | 无冲突 |
| SER ↔ LLM | ❌ 不会（SER 在 ASR 阶段） | 无冲突 |
| ASR ↔ TTS | ❌ 不会（先识别后合成） | 无冲突 |

## 9. 延迟分解

### 优化后时序

```
说话结束
  → 0ms 触发 SER（与 ASR 并行）
  → 600ms 尾部静音（rule2-min-trailing-silence=0.6）
  → ASR 完成
  → prompt 构建
  → Patient RAG 检索 (~20ms)
     ├→ RAG 命中 (conf≥0.30): TTS 合成 (~600ms) → 播放
     └→ LLM 推理 (~300ms) → TTS 合成 (~600ms) → 播放
```

注：TTS 合成 600ms 中包含进程创建 ~500ms + 推理 ~100ms（6秒音频 RTF=0.087×1000≈87ms）

### 关键优化点

| 优化 | 效果 |
|------|------|
| Qwen2-0.5B 替换 DeepSeek-R1 | 首 token 延迟从 ~800ms 降至 <200ms |
| 尾部静音 1.0s → 0.6s | 减少 400ms 静音等待 |
| RAG 直通路径 | 高置信度跳过 LLM，节省 ~300ms |
| Matcha TTS 替换 VITS/Paroli | RTF 从 1.01 降至 **0.087**，提升 11x |
| TTS 常驻 C daemon (FIFO pipe) | 零模型加载开销，合成仅 ~100ms |
| `num_threads=4` | 推理加速 6x（1.73s → 0.58s） |
