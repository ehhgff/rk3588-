## 二、各问题详细修复

### 2.1 解码器 rknn_lite y_mask 不兼容（根因）

**问题**：Python rknn_lite API 对该解码器 RKNN 模型存在兼容性问题。`y_mask` 输入张量不生效，导致 mask 帧（padding 帧）输出恒定噪声（peak=0.058, rms=0.020，数百帧完全一致）。

**验证**：
- `y_mask` 全 1（无 mask）：301 个不同峰值 → 说明 mask 逻辑有作用
- `y_mask` 正常（0=有效帧, 1=padding）：仅 7 个不同峰值 → 几乎恒定噪声
- 同模型通过 C++ `melotts_demo` 调用：**正常**（53 帧，尾部干净静音）

**结论**：该解码器模型必须通过 C++ 二进制调用，Python rknn_lite API 无法正确驱动。

### 2.2 subprocess 调用失败 — 缺少 cwd 参数

**问题**：`subprocess.run()` 调用 `melotts_demo` 时未设置 `cwd`（工作目录），二进制找不到模型文件（`./model/encoder-ZH_MIX_EN.rknn`），立即退出（~110ms, rc=0），未生成输出 WAV。

**修复**：`melotts_rknn_persistent.py:135` 添加 `cwd=MELOTTS_DIR`：

```python
# 修复前
result = subprocess.run(cmd, env=env, capture_output=True, text=True, timeout=30)

# 修复后
result = subprocess.run(cmd, env=env, cwd=MELOTTS_DIR, capture_output=True, text=True, timeout=30)
```

### 2.3 文件路径混淆 — /userdata/ 下有两份 melotts_rknn_persistent.py

**问题**：`melotts_service_rknn.py` 通过 `sys.path.insert(0, '/userdata')` 导入模块，加载的是 **`/userdata/melotts_rknn_persistent.py`**（6512 字节，旧版，无 `cwd` 参数）。而我一直推送的修复文件在 **`/userdata/voice_assistant/melotts_rknn_persistent.py`**（6529 字节，新版，有 `cwd` 参数）。同时 `.pyc` 缓存（`/userdata/melotts_rknn_persistent.pyc`）加剧了问题。

**根因**：
```
service.py 中 sys.path.insert(0, '/userdata')
  → 搜索 /userdata/ 目录
  → 找到 /userdata/melotts_rknn_persistent.py（旧版，无 cwd）← 加载这个！
  → 而非 /userdata/voice_assistant/melotts_rknn_persistent.py（新版，有 cwd）
```

**修复**：
```bash
cp /data/voice_assistant/melotts_rknn_persistent.py /userdata/melotts_rknn_persistent.py
rm -f /userdata/melotts_rknn_persistent.pyc
```

**教训**：推送修复时必须同时检查 `/userdata/` 根目录下的文件，不仅是 `voice_assistant/` 子目录。

### 2.4 播放设备号错误 — 用了 plughw:0,0 和 plughw:3,0

**问题**：用户听不到声音。测试时用了 `aplay -D plughw:0,0`（AB13X USB Audio）和 `aplay -D plughw:3,0`（板载 es8388），但实际音箱是卡在 card 1 的 USB2.0 Device。

**开发板 ALSA 设备列表**：

| Card | 名称 | 用途 |
|------|------|------|
| 0 | AB13X USB Audio | USB 音箱（另一设备） |
| **1** | **USB2.0 Device** | **实际接入的音箱（语音助手配置）** |
| 2 | rockchip-dp0 | DisplayPort 音频 |
| 3 | rockchip-es8388 | 板载扬声器 |
| 4 | rockchip-hdmi0 | HDMI 音频 |

**修复**：始终使用 `plughw:1,0` 播放。语音助手配置在 `streaming_vad.py` 中已正确：
```python
PLAY_DEVICE_NAMES = ["USB2.0 Device"]
PLAY_DEVICE = _find_device(_play_devices, PLAY_DEVICE_NAMES, 'plughw:1,0')
```

### 2.5 音量持久化

**问题**：`amixer` 设置的音量重启后丢失。

**修复**：使用 `alsactl store` 保存 ALSA 混音器状态：
```bash
amixer -c 1 set PCM 30%
alsactl store   # 保存到 /etc/asound.state
```

同时 `streaming_vad.py` 的 `setup_audio()` 在每次启动时设置音量：
```python
subprocess.run(["amixer", "-c", "1", "set", "PCM", "30%"], capture_output=True)
```

## 三、最终架构

```
服务启动（service_daemon.sh）:
  ├── melotts_service_rknn.py（常驻）
  │     ├── sys.path.insert(0, '/userdata')
  │     ├── import melotts_rknn_persistent
  │     │     └── G2PModule.load() → 加载 tokens.txt + lexicon.txt
  │     └── listen /tmp/melotts_service.sock

每次合成请求:
  └── MeloTTSInference.synthesize(text, output_path)
        ├── subprocess.run(
        │     cmd = [melotts_demo, --input_text, text, --output_filename, wav, --speed, 0.7]
        │     env.LD_LIBRARY_PATH = /data/melotts_demo/lib
        │     cwd = /data/melotts_demo        ← 关键修复
        │   )
        │   melotts_demo C++ 进程:
        │     ├── 加载 lexicon (~1.2s)
        │     ├── 加载 encoder.rknn
        │     ├── 编码器推理 (~140ms)
        │     ├── Duration 预测 (~4ms)
        │     ├── 加载 decoder.rknn
        │     ├── 解码器推理 (~1.47s)
        │     └── 写 WAV (format 3, 44100Hz, float32)
        └── 校验输出 WAV → 返回状态

播放:
  └── streaming_vad.py → aplay -D plughw:1,0 -q output.wav
```

**性能**：
| 阶段 | 耗时 |
|------|------|
| melotts_demo lexicon 初始化 | ~1.2s |
| 编码器推理 | ~140ms |
| Duration 预测 | ~4ms |
| 解码器推理 | ~1.47s |
| Python 校验开销 | ~0.5s |
| **合计（每次合成）** | **~3.3s** |

## 六、已知问题

### 6.1 每次合成 1.2s lexicon 初始化

`melotts_demo` 是单次进程，每次调用都需重新加载 lexicon（~1.2s）。无法通过 Python 端预热消除。解决方案方向：
- 将 `melotts_demo` 改造为常驻进程（需 C++ 修改）
- 通过 ctypes 直接调用 `melotts_demo` 内部的 `init_melotts_model` + `inference_melotts_model` 函数（该 binary 为 PIE、not stripped，但当前 dlopen 失败）

### 6.2 44100Hz float32 WAV 兼容性

`melotts_demo` 输出 WAV format 3（IEEE float 32-bit），部分播放器/工具不支持。`aplay` 提示 "Float 32 bit" 但实际播放无声。**必须通过 `plughw` 插件或 PulseAudio 播放**。
